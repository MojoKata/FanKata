# Fankata screenshots

```
screenshots/
  mocks/{dark,light}/     design mockups (generated by src/render.js)
  linux/{dark,light}/     the installed .deb on Ubuntu 22.04
  windows/{dark,light}/   the installed Windows build in a Windows 10 VM
  windows/desktop/        real captures of the Windows VM's screen: UAC prompt, installer, the app on the desktop
```

Dark is the primary design target: `mocks/dark` has every mockup, and `mocks/light` has the main ones.
The Linux and Windows folders have app screens 01–13, 16, 17 and 19 in both themes, driven by
`fankata --tour`. Most use simulated hardware (six fans, the same model on both platforms).
`16-fans-empty` and `19-troubleshoot-tips` show a PC with no fan control: on Linux an empty sysfs
with the service off, on Windows the VM's real hardware (it has no fan chip). `17-troubleshoot` is
Troubleshoot fans on the simulated machine, where everything is found.

## Generating

- **Mockups:** `node src/render.js` writes `mocks/dark/*.png` and `mocks/light/*.png`, with SVG sources in `src/svg/<theme>/`. It needs `@resvg/resvg-js` on `NODE_PATH`.
- **Linux:** `scripts/test-deb.sh`, which installs the `.deb` in containers and runs the tour.
- **Windows:** `scripts/test-windows-vm.sh`, which installs the setup `.exe` in the test VM and runs the tour there.
- Mockup curves are drawn with the same monotone cubic (PCHIP) evaluator the app uses. The mockups’ sparklines and Speed pulse trace are illustrative. In the app screenshots (linux/, windows/), sparklines are real: 45 s of the service’s 1-per-second samples from the simulated sensors.
